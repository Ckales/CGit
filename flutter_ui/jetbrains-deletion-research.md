# JetBrains three-pane deletion visualization

Checked 2026-11-12 against JetBrains' IntelliJ IDEA 2026.3 help and the public `JetBrains/intellij-community` `master` source. The supplied [Using Git integration](https://www.jetbrains.com/help/idea/using-git-integration.html) page is a Git documentation index; it links to the dedicated [Resolve Git conflicts](https://www.jetbrains.com/help/idea/resolve-conflicts.html) page, which contains the relevant three-pane description and color legend.

## What the official docs show

- The conflict-resolution page describes the left pane as the read-only local copy, the right pane as the read-only repository version, and the center as the editable result, initially set to the common base revision. It labels four separate visual states: modified line, deleted lines, newly added lines, and conflicting lines. See [Resolve Git conflicts](https://www.jetbrains.com/help/idea/resolve-conflicts.html#resolve-conflicts) and its [color legend image](https://resources.jetbrains.com/help/img/idea/2026.3/conflict_resolution_tool_legend.png).
- In that light-theme example, legend item 2 (“Deleted lines”) is a gray, full-line-height region in the center; item 4 (“Conflicting lines”) is a red-tinted line. This is a screenshot observation, not a promise of fixed RGB values: the page also provides a separate dark-theme image, and the implementation selects editor color-scheme attributes.

## What the source confirms

- The merge viewer passes each change's actual start/end line range from the paired panes to divider painting. The divider utility converts each pane's line range to its own editor y coordinates, applies that editor's vertical scroll offset, and paints a curved, full-width connector polygon between the two ranges. See [`MergeThreesideViewer.MyDividerPaintable`](https://github.com/JetBrains/intellij-community/blob/master/platform/diff-impl/src/com/intellij/diff/merge/MergeThreesideViewer.java#L1177-L1196), [`DiffDividerDrawUtil` scroll and coordinate mapping](https://github.com/JetBrains/intellij-community/blob/master/platform/diff-impl/src/com/intellij/diff/util/DiffDividerDrawUtil.java#L135-L139), [range-to-polygon mapping](https://github.com/JetBrains/intellij-community/blob/master/platform/diff-impl/src/com/intellij/diff/util/DiffDividerDrawUtil.java#L273-L301), and [curved full-width polygon drawing](https://github.com/JetBrains/intellij-community/blob/master/platform/diff-impl/src/com/intellij/diff/util/DiffDividerDrawUtil.java#L438-L506).
- An empty line range (`startLine == endLine`) has no filled text background. JetBrains places a line-separator marker at that boundary (top of the first line, otherwise bottom of the previous line); a nonempty range receives the line fill. This is the source basis for representing a deletion as a collapsed horizontal boundary on the pane with no retained line. See [`DiffDrawUtil.LineHighlighterBuilder`](https://github.com/JetBrains/intellij-community/blob/master/platform/diff-impl/src/com/intellij/diff/util/DiffDrawUtil.java#L595-L624).
- Divider geometry has a specific adjustment for the last-line deletion case, and the polygon uses a one-pixel edge when a side has less than two pixels of height. See [`DividerPolygon.paint` and `withAlignedHeight`](https://github.com/JetBrains/intellij-community/blob/master/platform/diff-impl/src/com/intellij/diff/util/DiffDividerDrawUtil.java#L462-L520).
- Deletion and conflict are different semantic diff types, not two treatments of one red conflict type: `MergeConflictType.DELETED` maps to `TextDiffType.DELETED`, while `CONFLICT` maps to `TextDiffType.CONFLICT`; those use separate `DIFF_DELETED` and `DIFF_CONFLICT` color-scheme keys. See [`DiffUtil.getDiffType`](https://github.com/JetBrains/intellij-community/blob/master/platform/diff-impl/src/com/intellij/diff/util/DiffUtil.java#L1578-L1585) and [`TextDiffTypeFactory`](https://github.com/JetBrains/intellij-community/blob/master/platform/diff-impl/src/com/intellij/diff/util/TextDiffTypeFactory.java#L22-L33). For unresolved changes, the divider painter fills with the type color and sets no border; its dotted border is used for resolved changes. See [`ResolvablePainter`](https://github.com/JetBrains/intellij-community/blob/master/platform/diff-impl/src/com/intellij/diff/util/DiffDividerDrawUtil.java#L339-L368).

## Geometry recommendation for CGit

For a pure deletion, retain the real line ranges on both panes. On the side with no corresponding retained lines, use a zero-height range at the deletion boundary and draw a thin horizontal boundary there; do not add placeholder text or a synthetic row. On the pane that contains the retained block, shade those actual lines across the content width using the deletion diff color (gray in JetBrains' light-theme example), without conflict-red styling. Connect the collapsed boundary to the full-height block with a filled curved divider spanning the divider width. Compute both connector endpoints from their own pane's line geometry and current vertical scroll offset so panes may scroll independently. Reserve conflict red for a change actually classified as a conflict.

The documentation screenshot establishes the visual target; the source establishes the empty-range marker, color categories, and connector construction. Mapping that model onto CGit's own pane layout is an implementation inference, not a JetBrains compatibility guarantee.
